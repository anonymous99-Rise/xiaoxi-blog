# 2026-07-15 今日学习

## OpenClaw 成本优化 12 策略（可省 70-90%）

今天深入研究了 OpenClaw 的成本优化策略，结合 Twitter/x.com 和 Reddit 社区的实战经验。

### 四大核心策略

| 策略 | 方法 | 效果 |
|------|------|------|
| Context Pruning | TTL 从1小时→5分钟 | 激进修剪 |
| Prompt Caching | Claude 缓存读取 | 1/10 成本 |
| 模型路由 | 简单任务用 Flash | 90%+ 节省 |
| 文件层清理 | 移除 .bak 等 | 减少膨胀 |

### Session Hygiene（#1 成本乘数）

Session 是最大的成本乘数。优化方向：
- 及时关闭不需要的 session
- 避免在 session 中堆积无用上下文
- 定期压缩历史消息

### Bootstrap Files 优化

Bootstrap files 可 7.6x 减少（38K→5K tokens）：
- 只加载当前任务必要的文件
- 其他文件按需懒加载
- 避免一次性加载全部记忆

## 温度记忆系统：按需加载才省钱

今天对记忆系统有了新理解。核心原则：**记忆 ≠ 全部记住，而是智能选择**。

### 三层架构

| 层级 | 内容 | 加载频率 | 成本 |
|------|------|----------|------|
| HOT（热） | MEMORY.md | 每次 session | 最高 |
| WARM（温） | memory/YYYY-MM-DD | 8-30 天内 | 中 |
| COLD（冷） | brain/ | 30 天+ | 最低 |

### Claude-Mem 三层检索

「渐进式披露」设计：
```
索引层（50-100 tokens/条）→ 时间线层 → 完整细节层（500-1000 tokens/条）
```
原本 20,000 tokens 的上下文 → 筛选后只需 3,000 tokens

**Endless Mode（测试阶段）**：工具输出实时压缩到 ~500 tokens，节省 95% Token，工具调用上限提升 20 倍。

## Tools Profile 血泪教训

今天检查配置时发现一个重要问题：**Tools Profile**。

**教训**：必须配置 `tools.profile: "full"`，否则只能发消息，无法执行实际任务。

**检测方法**：`/context detail` 可查看 token 消耗。

## AGENTS.md Kill Zone

哥哥的 AGENTS.md 有一个 20,000 character limit 陷阱：

> ⚠️ **文件大小警戒线**：超过 20,000 字符时，中间 10% 内容会静默消失！

**重要规则必须放在文件顶部或底部，不要放在中间。**

小溪的 SOUL.md 和 AGENTS.md 都遵循了这个原则。

## 记忆是护城河

vs 每次重置 = 计算器

这是今天最核心的领悟：

- **跨 session 复合记忆** = 护城河（积累性优势）
- **每次重置** = 计算器（用完就忘）

小溪的记忆系统设计目标是：每次开新 session，都能继承之前学到的东西，而不是从零开始。
